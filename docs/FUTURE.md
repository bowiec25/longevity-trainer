# Future extensions

Ideas for later milestones, so they don't get lost. Each line says **what**, **why**, and **what already makes it easier**. When one gets planned into a milestone, move it to `docs/PLAN.md` and mark it here.

| Idea | Why | Already makes it easier | Where it would go |
|---|---|---|---|
| **quizkit as its own repo** (added 2026-11-12) | Today quizkit is copied from `mandarin-hsk-trainer` (commit `caa969a`), so the two copies can drift. When a fix needs to flow between the projects, one shared package is better | quizkit already has no Mandarin code (a scan test guards it), only needs `pydantic` + `rapidfuzz`, and the copy records its source commit | A small `quizkit` repo; both projects `uv add git+https://...@<sha>` |
| **Dated-fact cards from primer Parts 3–5** (added 2026-11-12) | Prices, companies, trials, regulators and deals are a big part of the primer, but they go stale within months | The card kinds (PLAN.md) already include "dated fact" with an "as of" date; M5 builds the freshness re-check | After M5: dated cards that expire and get re-checked |
| **Receipt check in CI** (added 2026-11-12) | Today the real-PDF quote test skips in CI, so only local runs prove the quotes | The download is pinned by SHA-256, so CI could fetch and cache it | A CI step that downloads the pinned sources (cached) and runs `longevity check-receipts` |
| **Save exam results as files** (added 2026-11-12) | Exam runs are by hand and their scores live only in SETUP_LOG, so runs can't be compared over time | `ExamReport.model_dump()` already includes `passed` | `check-cards-exam` appends each report (model, prompt version, scores, cost) to a results file |
| **Tune the card checker** (added 2026-11-12) | It rejects about 30% of good cards (bar: ≤ a third); some rejections are fair strictness, some not (`ev-rapa-why`, `ev-pearl-women`, `ev-pearl-catch`) | Exam + held-out set + `check-cards-exam`; prompt v2 in `card_checker` | Grow the held-out set first (12 is small), then tune on the main exam only and judge by held-out; aim for ≤ 1 in 6 |
| **Marking eval set** (added 2026-11-12) | Claude now marks answers (`marking` block), but nobody has measured how often it agrees with you | `quizkit.blocks.judge` has eval-style scoring | ~20 answers you label right/wrong (incl. a partial answer, an oversold one, a mice→people swap); score agreement |
| **Dispute Claude's mark** (added 2026-11-12) | Today Claude's "no" is final | The CLI already has a "count it as right?" prompt for unchecked answers | Let you override, and log overrides to grow the eval set |
| **Source checker, postponed** (added 2026-11-12) | `source_vetter` (tier, publisher, preprint, licence) and the fan-out source finder were M2 Steps 4–6 | `docs/SOURCE_FORMATS.md` has the findings; ADR 0007 the rules | Pick up when cards need many more sources |
| **`by_mode` judge helper in quizkit** (added 2026-11-12) | `marking` routes questions to a judge by card kind; generic, but only one quiz uses it | Rule of two: lift it when a second quiz routes by mode | `quizkit.blocks.judge.by_mode({mode: Judge})` |
| **Official APIs for sites that block programs** (added 2026-11-12) | NIH supplement fact sheets, NIA and CDC are top tier-A sources but refuse plain downloaders | `docs/SOURCE_FORMATS.md` lists them; some publish data through official APIs | Check each for an API meant for programs; add a fetcher per API |
| **"Check the primer" report** (added 2026-11-12) | Finding receipts for primer facts also shows where the primer is wrong, out of date, or unsupported | Every card's receipt check (M3) runs anyway | A list of primer claims that found no trusted source, or a different number, to fix in the primer's next version |
| **Writer: make the "how" card reliable** (added 2026-11-12) | In 2 of 6 v2 runs the only missing ask was "how", so the run missed the bar | The report already says which asks were kept | Ask for at least one card per ask, or a second small call for a missing ask |
| **Writer: long sources** (added 2026-11-12) | One call takes up to 200,000 characters; the hallmarks review fits, a book wouldn't | `[page N]` markers already split the text | Split by section and write per section (maybe the Agent SDK with tools, ADR 0008) |
| **Mechanism sources for drugs and supplements** (added 2026-11-12) | Rapamycin has no "how" card: PEARL is a trial report. Your steer: more science on drugs, supplements, hallmarks and factors | ADR 0007's tiers; `write-cards --add` | Pin a mechanism review per drug or supplement (rapamycin/mTOR, metformin, NAD+, senolytics…), then `--add` |
| **Near-repeat questions** (added 2026-11-12) | `--add` drops exact repeats and shows the writer the bank's questions, but a reworded repeat could still slip through | The checker or a cheap similarity check | Flag pairs of cards that ask the same thing |
| **Store each card's ask** (added 2026-11-12) | The coverage line reads a card's ask from its id (`<topic>-<ask>-<k>`); hand-made cards don't count | `LongevityCard` in `card_bank` | An optional `asks` field on cards |
| **Lift `Saver` into quizkit** (added 2026-11-12) | HSK and longevity each have a "save each answer, warn once on a busy file" helper; the rule of two is met | `quizkit.progress.save_attempt` | One `quizkit.progress.Saver(store, skill)`, used by both |
| **Stats in one read** (added 2026-11-12) | `stats` asks quizkit's `skill_stats` once per topic group, re-reading the file each time; fine at 63 cards | `skill_stats` | Read boxes and answers once and split by group, if stats gets slow |
| **Port the shared eval scorer to HSK** (added 2026-11-12) | quizkit gained `score` / `ScoreItem` / `verdict_mark` (judge eval) and `load_jsonl_file` here; HSK's copy of quizkit doesn't have them | HSK's `quizkit/blocks/judge/eval.py`, `jsonl_loader` | Copy the two changes back with their tests (rule of two: both quizzes now use them) |
| **Grow the marking eval** (added 2026-11-12) | 23 cases, mostly hallmarks; the 2 misses were short-but-right answers | `tests/data/marking_eval.jsonl` | Add cases from real play (answers you overrule) and from the drugs and clocks topics; revisit the concept rubric if short-but-right answers keep failing |
| **Two more JSONL readers onto `load_jsonl_file`** (added 2026-11-12) | quizkit's judge eval `load_cases` (no BOM handling, `splitlines`) and the card checker's exam loader read JSONL by hand | `quizkit/blocks/judge/eval.py`, `card_checker` | Switch both to `load_jsonl_file`, with a test that a BOM file loads |
| **A generic quizkit web-quiz brain** (added 2026-11-12) | HSK's `WebQuiz` and longevity's `QuizScreen` share a shape (phases, stale-click guard, save on final) but each has quiz-specific parts | `quizkit` | Lift the shared phase machine when a third quiz needs a web page |
