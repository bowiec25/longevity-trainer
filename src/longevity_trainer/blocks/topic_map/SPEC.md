# Block: `topic_map`

> **In plain words:** Sort the cards onto broad shelves: map each card's topic to its topic-map entry and that entry's area (How we age, Drugs & treatments, ...)

## Goal
Sort the cards onto broad shelves: map each card's topic to its topic-map entry and that entry's area (How we age, Drugs & treatments, ...)

A bookshop: the web page's topic box lists the **shelves** (areas), and each card is a book on one. Before this, the box mixed levels ("hallmarks" next to "metformin"; user, 2026-11-18: "metformin and rapamycin are like drugs category, not their own"). The shelves live in `data/topics.jsonl` (each topic's `area`), so moving a topic to another shelf is a data change, not a code change. It also ties every card to its topic-map entry, so a card filed under another name (`physical-activity`, whose entry is `exercise`) is found through the entry's `aliases`.

**Parts, so you learn them all** (user, 2026-11-18: "as a learner it's important I learn all"): a topic can list its **parts**, e.g. the 12 hallmarks. A card on one part is filed `"<topic>: <part>"` (e.g. `"hallmarks: cellular senescence"`), and a coverage report shows, per part, whether easy mode has a "what" card and a "how" card for it. The gaps are what to write next.

**Writing cards for one part:** `write-cards --topic "hallmarks: <part>"` (a new per-part card file, e.g. `hallmarks-cellular-senescence.jsonl`). The four older bundle files (`hallmarks-genome-telomeres-and-epigenetics.jsonl` etc.) keep their re-filed cards but take no `--add`: adding with the old bundle topic would file new cards under no part, and the real-data test below would fail.

**The whole syllabus, chapter by chapter** (user, 2026-11-18: "lets make sure we dont have gaps elsewhere too"): a library's stock list. Every learnable sub-topic (each `status: "v1"` line, filed under its primer chapter) shows its easy and hard cards and whether easy mode covers it, so an empty shelf can't hide. The primer's chapters are the **topics**; the lines of `data/topics.jsonl` are their **sub-topics**. The chapter names in `CHAPTERS` are our own short words, not the primer's text.

**Priorities, so the important things come first** (user, 2026-11-18: "we might need a way of prioritizing the important stuff"): each learnable sub-topic has a `priority`: **core** (what a longevity expert must know: the basics, the hallmarks and pathways, the big ideas, the evidence skills, the main drugs, lifestyle, peptides, blood markers and clocks), **useful** (the second wave) or **extra** (last). The report shows the score per tier, and `coverage --todo` lists what to fill next, core first.

**Not in scope:** dealing cards (`study`), the page (`web_pages/quiz.py`), the card writer's own topic list (`card_writer.load_topics`).

## Kind
**script.** Looking up a topic in a table needs no judgment, and code can check every answer.

## Inputs
| Input | Type | Plain meaning |
|---|---|---|
| `path` | `Path \| None` | The topic map file (default `None`: `TOPICS_FILE`, looked up when called) |
| `card_topic` | `str` | A card's `topic`, e.g. `"hallmarks: senescence"`, `"rapamycin"`, `"NAD+ boosters"` |
| `topics` | `list[Topic]` | The loaded topic map |
| `cards` | `list[LongevityCard]` | Cards to sort onto shelves (or to count per part) |
| `topic_id` | `str` | For `coverage_lines`: the topic whose parts to report, e.g. `"hallmarks"` |

**How it's called** (importable from `longevity_trainer.blocks.topic_map`):
```python
topics = load_topic_map()
area_of("hallmarks: cellular senescence", topics)  # "How we age"
areas_in(load_cards(), topics)  # ["How we age", "Big ideas", "Drugs & treatments", ...]
coverage_lines(load_cards(), topics, "hallmarks")  # the report below
misfiled(load_cards(), topics)  # [] when every part-card names a real part
syllabus_lines(load_cards(), topics)  # every chapter and sub-topic, and the gaps
todo_lines(load_cards(), topics)  # what to fill next, core first
```

**From the command line:** `uv run longevity coverage <topic id>` prints `coverage_lines` (exit 0). An unknown topic, or one without parts, gives one line naming the topics that have parts (exit 1). `uv run longevity coverage` with no topic prints `syllabus_lines` (exit 0); `uv run longevity coverage --todo` prints `todo_lines` (exit 0; `--todo` with a topic → argparse error, exit 2). A topic map or card bank that can't be read → one line, exit 1. It never calls Claude.

## Outputs
| Output | Type | Plain meaning |
|---|---|---|
| `TOPICS_FILE` | `Path` | `ROOT / "data" / "topics.jsonl"` |
| `AREAS` | `tuple[str, ...]` | The shelves, in the order the page shows them: `("How we age", "Big ideas", "Drugs & treatments", "Supplements", "Lifestyle", "Measuring ageing", "Evidence & trials", "Industry")` |
| `Topic` | pydantic model | One topic-map line: `id`, `topic`, `group`, `area` (one of `AREAS`), `status`, `aliases: list[str] = []` (other names cards may be filed under, e.g. `["physical-activity"]`), `parts: list[str] = []` (the named parts a learner should cover, e.g. the 12 hallmarks; a card on one is filed `"<topic id or alias>: <part>"`), `primer: str = ""` (its primer section, e.g. `"2.1"`, `"11.4-11.5"`, `"5"`), `kinds: list[str] = []` (the card kinds it should have, e.g. `["name", "explain"]`), `priority: str = ""` (`"core"`, `"useful"`, `"extra"`, or `""` for none; anything else → `ValueError` naming the line; `load_topic_map` requires one on every `v1` line and none on other lines; `syllabus_lines` and `todo_lines` still handle topics without one, as a caller may build `Topic`s directly). Other keys in the line are allowed and ignored |
| `CHAPTERS` | `dict[int, str]` | Our short name for each primer chapter 0–23: `0` "How to read the evidence", `1` "What ageing is", `2` "Hallmarks and pathways", `3` "Big ideas", `4` "Judging the evidence", `5` "Consumer longevity", `6` "Drugs", `7` "Peptides", `8` "Hormones", `9` "Supplements", `10` "Procedures and lifestyle", `11` "Blood tests", `12` "Ageing clocks", `13` "Scans", `14` "Wearables", `15` "Glucose and genes", `16` "Health data", `17` "The drug pipeline", `18` "Landmark trials", `19` "Regulators", `20` "Money and deals", `21` "What changed", `22` "Where the news is", `23` "People, events and books" |
| `syllabus_lines(cards, topics)` | `list[str]` | The whole-syllabus report. Only topics with `status == "v1"` are listed (the learnable ones). **A topic's chapter** = the whole number its `primer` starts with (`"2.1"` → 2, `"11.4-11.5"` → 11, `"5"` → 5); no leading number → no chapter. **A topic's cards** = cards whose group finds it (as `area_of` does), any part. **what** / **how** / **hard** are counted as in `coverage_lines`. **A topic without parts is covered** when it has every easy card its `kinds` call for: an easy what if `kinds` has `name`, `term` or `fact`; a how card (any level) if `kinds` has `explain`; if `kinds` has neither (empty, or only `grade`), any one easy card. **A topic with parts is covered** when every part is covered (as in `coverage_lines`). **Lines:** first `"Syllabus: <c> of <n> sub-topics covered (an easy what card and a how card)"`, then `"By priority: core <c> of <n>, useful <c> of <n>, extra <c> of <n>"` (v1 topics; a tier with no topics shows `0 of 0`; v1 topics with no priority add `, none <c> of <n>` only when there are some), then per chapter in number order (chapters with at least one v1 topic): `"<NN> <chapter name>: <c> of <n> covered"` (`NN` two digits, `00`–`23`; name from `CHAPTERS`, or `"chapter <k>"` if missing), then one line per topic in file order: without parts `"  <id>: <w> easy what, <h> how; <x> hard"` ending `" ✓"` or `" (needs: <list>)"` where the list is what's missing of `easy what`, `a how card`, `an easy card`; with parts `"  <id>: <p> of <m> parts covered (see: coverage <id>)"` ending `" ✓"` when all are. v1 topics with no chapter go last under `"?? no chapter: <c> of <n> covered"`. Then the topics not listed, by status: `"Later (dated facts, wait for M5): <a> sub-topics"` (status `after-m5`) and `"Read, don't quiz: <r> sub-topics"` (status `read`), always both; any other non-v1 status adds a last line `"Other status: <o> sub-topics"` only when there are some |
| `load_topic_map(path=None)` | `list[Topic]` | Every line of the file as a `Topic`, in file order (all statuses); blank lines skipped |
| `area_of(card_topic, topics)` | `str \| None` | The card's shelf: take the card topic's group (the text before the first `:`, as `study.group_of`), slug it (lower case, letters/digits/hyphens, the same rule as `card_writer.slug`, kept in this block so quiz-time code doesn't import the card writer: `"NAD+ boosters"` → `nad-boosters`), and find the topic whose `id` or one of whose `aliases` equals it; return that topic's `area`. No match → `None` |
| `coverage_lines(cards, topics, topic_id)` | `list[str]` | The parts report. **First line:** `"<the topic's id>: <c> of <n> parts covered (each needs an easy what card and a how card)"`. **Then one line per part, in the topic's order:** `"  <part>: <w> easy what, <h> how; <x> hard"`, ending `" ✓"` when covered or `" (needs: easy what)"`, `" (needs: a how card)"` or `" (needs: easy what, a how card)"`. A card counts for a part when its group finds this topic (as `area_of` does) and the text after the first `:` slugs to the part's slug. **what** = kind `name`, `term` or `fact` (recall), counted only if `difficulty == "easy"`; **how** = kind `explain` at **any level**: easy, hard or untagged. **Covered** is not "all in easy mode": easy mode deals only easy cards (your primer's facts), so a hard how card is learned in hard mode; that's why the reports say "covered", not "covered in easy mode" (code review, 2026-11-19) (user, 2026-11-19: the primer gives most sub-topics one line, so an easy "how" is rarely possible; a well-sourced how card beyond the primer still counts); **hard** = every card on the part that isn't easy (untagged included, any kind, so a hard how card is counted in both). `topic_id` is found like a card's group: slugged, by id or alias (`"Hallmarks"` works). Unknown `topic_id`, or a topic with no parts → `ValueError` naming the topics that have parts |
| `todo_lines(cards, topics)` | `list[str]` | What to fill next. The v1 topics **not** covered (covered as in `syllabus_lines`), grouped by tier in the order core, useful, extra, then no priority; file order within a tier. Per tier with at least one such topic: a heading `"<Core, Useful, Extra or No priority>: <k> to fill"`, then one line per topic `"  <NN> <id>: needs <the missing cards, joined with ', '>"` (`NN` its chapter, two digits, or `??`; the missing cards worded as in `syllabus_lines`: `easy what`, `a how card`, `an easy card`), or for a topic with parts `"  <NN> <id>: <p> of <m> parts covered"`. Nothing to fill → the single line `"Nothing to fill: every sub-topic is covered"` |
| `misfiled(cards, topics)` | `list[str]` | One line per card filed `"<group>: <x>"` whose group finds a topic **with parts** but whose `x` is none of them: `"<card id>: '<x>' isn't one of <topic id>'s parts"`. Cards filed under the topic alone (`"hallmarks"`), and topics without parts, are fine. Empty = all filed well |
| `areas_in(cards, topics)` | `list[str]` | The shelves that hold at least one of the cards, in `AREAS` order, each once (what the page's box offers). Cards with no shelf are left out |

## Failure modes
| Situation | What it does |
|---|---|
| The topic map file is missing | `load_topic_map` raises `FileNotFoundError` |
| A line isn't JSON, isn't an object, or lacks a string `id` / `topic` / `group` / `area` / `status` | Raises `ValueError` naming the line number |
| A line's `area` isn't one of `AREAS` | Raises `ValueError` naming the line number and the area |
| A `kinds` entry isn't one of `name`, `term`, `fact`, `explain`, `grade` (a typo would silently change what the topic needs) | Raises `ValueError` naming the line number and the kind |
| A line's `priority` isn't `core`, `useful`, `extra` or `""` | Raises `ValueError` naming the line number (`bad priority`) |
| A `v1` line has no priority, or a line that isn't `v1` has one (it would be counted nowhere) | Raises `ValueError` naming the line number: every learnable sub-topic needs a tier, and only those |
| A topic's `parts` repeat (same slug), or a part slugs to nothing (`""`, `"---"`) | Raises `ValueError` naming the line number |
| An `id` repeats, or an alias equals another topic's id or alias | Raises `ValueError` naming the line number (a card name must lead to one topic) |
| A card's topic matches no id or alias | `area_of` returns `None`; `areas_in` leaves the card out (the real-data test below keeps the bank from having such cards) |

## How to test
Automatic tests in `tests/blocks/test_topic_map.py`, with small topic files written in the test:
- **load_topic_map:** reads every line in order (all statuses), skips blank lines, `aliases` defaults to `[]`, `primer` defaults to `""` and `kinds` to `[]`, and are read when given; other extra keys (e.g. `"note"`) are accepted; missing file → `FileNotFoundError`; not JSON, not an object, a missing or non-string required field → `ValueError` naming the line; a non-string `primer` (`2.1`) or a non-list `kinds` (`"name"`) → `ValueError` naming the line; a kind `"explian"` → `ValueError` naming the line and the kind; an unknown area → `ValueError` naming it; a repeated id, an alias equal to another id, and an alias used twice → `ValueError`; with no argument it follows a monkeypatched `TOPICS_FILE`
- **area_of:** `"hallmarks: senescence"` → the `hallmarks` topic's area; `"NAD+ boosters"` → `nad-boosters`'s; `"Physical Activity"` → found through an alias; an unknown topic → `None`
- **parts:** `parts` defaults to `[]`; a repeated part (`"Dysbiosis"` and `"dysbiosis"`) → `ValueError` naming the line; a blank part (`""` or `"---"`) → `ValueError` naming the line
- **coverage_lines** (a small topic with 3 parts, hand-made cards): the first line's count; a part with an easy `name` and an easy `explain` card → `✓`; an easy `name` and a hard `explain` → `✓` (the explain also counts in hard); an easy `name` and an untagged `explain` → `"1 easy what, 1 how; 1 hard ✓"`; a hard `name` and an easy `explain` → `(needs: easy what)`; easy `term` and easy `fact` count as what; a part with only hard cards → `(needs: easy what, a how card)` and the hard count; `coverage_lines(..., "Hallmarks")` and an alias of the topic work like the id; untagged cards count as hard; card topics match by slug (`"Hallmarks: Cellular Senescence"`); a card filed under the topic alone counts for no part; parts listed in the topic's order; an unknown topic and a topic without parts → `ValueError` naming the topics with parts
- **misfiled:** a card on an unknown part is named (also when filed through the topic's alias); a card on a real part, a card on the topic alone, and a card on a topic without parts are not
- **syllabus_lines** (a small topic file with topics in chapters 1 and 2, one with parts, one non-v1; hand-made cards): the first line counts covered v1 topics; chapters in number order with two-digit numbers and `CHAPTERS` names; topics in file order under their chapter; a topic whose `kinds` are `["term", "explain"]` with an easy term and an easy explain card → `✓`; with only an easy term → `(needs: a how card)`; with only hard cards → `(needs: easy what, a how card)` and the hard count; `kinds` `["explain"]` needs only a how card; `kinds` `["grade"]` or `[]` → `(needs: an easy card)` until any easy card (a lone hard `explain` doesn't cover it: with no kinds, an easy card is the bar); a topic with parts shows `<p> of <m> parts covered` and is covered only when every part is (also when its id isn't a slug, e.g. `"Hall_marks"`: its parts are counted on the topic itself, not looked up again by name); `primer` `"11.4-11.5"` is chapter 11; a v1 topic with no leading number goes under `?? no chapter`; an `after-m5` topic and a `read` topic aren't listed and are counted in their own lines (`Later (dated facts, wait for M5): 1 sub-topics`, `Read, don't quiz: 1 sub-topics`); no `Other status` line without other statuses, and `Other status: 1 sub-topics` with one; a card filed through an alias counts for its topic; `CHAPTERS` has the 24 chapters 0–23
- **priority:** `priority` defaults to `""` (a `Topic` built directly); `"core"`, `"useful"`, `"extra"` load on v1 lines; `"high"` or a number → `ValueError` naming the line; a v1 line without a priority → `ValueError` naming the line; an `after-m5` line with a priority → `ValueError` naming the line; `syllabus_lines`' second line counts covered / total per tier, with `0 of 0` for an empty tier, and a `none` part only when a v1 topic has no priority
- **todo_lines:** only uncovered v1 topics are listed (not covered ones, not non-v1 ones); tiers in the order core, useful, extra, no priority, each with its heading count; file order within a tier; exact lines like `"  01 gompertz: needs a how card"`, `"  01 healthspan: needs easy what, a how card"`, `"  00 evidence-grades: needs an easy card"` (kinds `["grade"]`), a topic with parts `"  02 hallmarks: 1 of 12 parts covered"`, no chapter `"  ?? x: needs easy what"`; everything covered → the single "Nothing to fill" line
- **CLI** (`longevity coverage`, a temporary topic file and cards via monkeypatched `TOPICS_FILE` / `cli.CARDS_DIR` or `load_cards`): prints the lines, exit 0; an unknown topic → one line, exit 1; no topic → the `syllabus_lines`, exit 0; `--todo` → the `todo_lines`, exit 0; `--todo hallmarks` and `--todo ""` → exit 2; the missing / not-JSON map and bad card file cases also with `--todo`; `coverage_command("hallmarks", todo=True)` called directly → one line, exit 1; a missing or not-JSON topic map → one line, exit 1, both with and without a topic; a bad card file → one line, exit 1, both with and without a topic
- **areas_in:** shelves in `AREAS` order (not card order), each once; a card with no shelf is left out; no cards → `[]`
- **Real data:** the real `data/topics.jsonl` loads; every card in the real bank (`load_cards()`) has a shelf (so a new card file under an unknown name fails CI: give its topic an alias or use the topic id); `rapamycin` and `metformin` are on `"Drugs & treatments"`, `hallmarks` on `"How we age"`; `hallmarks` has the 12 parts of the 2023 review (genomic instability, telomere attrition, epigenetic alterations, loss of proteostasis, disabled macroautophagy, deregulated nutrient-sensing, mitochondrial dysfunction, cellular senescence, stem cell exhaustion, altered intercellular communication, chronic inflammation, dysbiosis); every v1 topic in the real map has a priority (core, useful or extra) and a chapter in `CHAPTERS` (checked on `syllabus_lines`' own output: no `?? no chapter` and no `chapter <k>` fallback header; the chapter counts add up to the first line's total); `misfiled(load_cards(), load_topic_map()) == []` (every hallmark card names one hallmark, or is filed under `hallmarks` alone)
- **Contract test:** folder parts exist and `BLOCK_SPEC` matches this SPEC
