# Block: `card_writer`

> **In plain words:** Draft quiz cards on one topic from one pinned source, keep only those whose quote is really in the source and that pass the card checker.

## Goal
Draft quiz cards on one topic from one pinned source, keep only those whose quote is really in the source and that pass the card checker.

It's the student writing flashcards from a textbook. Claude reads the source and drafts cards that cover the questions per topic (what is it, how does it work, how sure are we, what's the catch, and **what does it connect to**: a link from this topic to another topic in the syllabus, e.g. "Which cell growth switch does rapamycin turn down?" → mTOR, so the bank builds a map of the field, not a pile of separate facts; user, 2026-11-13); then the gates, in order: **code** checks each card's shape, that a connect card names a real other topic (`data/topics.jsonl`), and finds its quote word for word in the source (`receipts`); **code** drops repeats; the **card checker** (`card_checker`, Haiku) rejects any card that breaks a rule. What survives is written to `data/cards/<topic>.jsonl` and plays in `longevity quiz`.

**Not in scope:** finding or pinning sources (records in `data/sources/`, documents via `receipts.ensure_source`); trend cards (rule 7, M5); fixing rejected cards (the next run drafts again); marking answers (`marking`).

## Kind
**agent.** Writing a good question needs judgment. One Claude call per run via `claude -p` (no tools, no Agent SDK: ADR 0008), reply forced by a JSON schema; then the script gates above validate every card. Quality is measured by the writer eval (How to test).

## Inputs
| Input | Type | Plain meaning |
|---|---|---|
| `topic` | `str` | What the cards are about, e.g. `"rapamycin"`. Becomes each card's `topic` and, slugged (lower case, letters/digits/hyphens), the start of its id and the file name |
| `source_id` | `str` | The pinned source to write from (`data/sources/<source_id>.json`) |
| `n` | `int` | How many cards to ask Claude for (default 8, 1–20) |
| `ask` | callable | How to reach Claude (default quizkit's `ask_claude`). Tests pass a fake |
| `model` | `str` | The writer's model (default `"sonnet"`) |
| `check` | `Callable[[LongevityCard], CardVerdict]` | The card checker (default `card_checker.check_card`, Haiku). Tests pass a fake |
| `taken_ids` | `set[str]` | Card ids already in the bank, so new ids never clash (default: empty) |
| `taken_questions` | `set[str]` | Questions already in the bank, so a run never repeats one (compared case- and space-insensitively; default: empty) |
| `sources_dir` | `Path` | Where source records live (default `data/sources`) |
| `root` | `Path` | The project root the record's `local_path` is relative to (default `ROOT`) |
| `fetch` | `Callable[[str], bytes]` | Downloads a missing document (default quizkit's `http_get`). Tests pass a fake |
| `pages` | `tuple[int, int] \| None` | Only write from these pages of the source: first and last, 1-based, inclusive, e.g. `(9, 12)` (default `None`: the whole source). For long sources, one section at a time: a long review can't go in one call, and one run over all of it would only skim it |
| `topics` | `dict[str, str] \| None` | The topics a connect card may link to: topic id → its one-line description (default `None`: `load_topics()`, the `v1` topics in `data/topics.jsonl`) |

**How it's called** (importable from `longevity_trainer.blocks.card_writer`):
```python
result = write_cards("rapamycin", "pearl-2025", n=8, taken_ids=ids)  # WriterResult
result = write_cards("hallmarks: senescence", "hallmarks-of-aging-2023", pages=(17, 20))
```
From the command line: `uv run longevity write-cards --topic rapamycin --source pearl-2025 [--n 8] [--model sonnet] [--pages 17-20] [--dry-run] [--add | --replace]`. `--pages` takes `A-B` or a single page `A` (= `A-A`); anything else (`x`, `5-`, `0-3`, `9-4`) is an argparse error (exit 2, before any Claude call). It prints one line per draft (kept, or the gate that dropped it and why) and the report (its counts include `link <n>`, the drafts dropped at the link gate). Without `--dry-run`, and only if the report passes, it writes the kept cards to `data/cards/<topic-slug>.jsonl` (a run that misses the bar writes nothing: look at its drops, then run again). If that file exists it refuses (exit 1, one line naming `--add` and `--replace`) unless one of them is given: **`--add`** keeps the file's cards and appends the new ones after them (growing a topic over time); **`--replace`** overwrites it. Giving both is an argparse error (exit 2). `--add` on a topic with no file yet just writes it. At the end it prints one **coverage** line for the topic file as it now stands (after a dry run: as it would stand): the topic file's existing cards (with `--add`, or a dry run without `--replace`) plus this run's kept cards if it passed (with `--replace` or no file: only the kept cards). It says which of what / how / how_sure / catch / connect they cover, and which of what / how / how_sure are still missing ("run again with --add"). It is printed also when the run doesn't pass (then it describes the file unchanged), but not when the write fails. A card's ask is read from its id (`<slug>-<ask>-<k>`, `how-sure` = how_sure); cards whose id doesn't follow that pattern don't count. The file is written to `<file>.tmp` first and then swapped in, so a failed write keeps the old cards (exit 1, one line). `--dry-run` drafts and gates but writes nothing, and is allowed when the file exists (it still calls Claude: it's for looking before saving); without `--replace` it treats an existing topic file like `--add` does (its ids and questions are taken), so it shows what `--add` would keep. **One read:** the topic file is read once, before the Claude call; if its content has changed by the time of writing (another run, a hand edit; a file that appeared during the run counts as changed), it writes nothing and exits 1 with one line ("… changed during the run, run again"), so two runs can't hand out the same id. After the report it prints one line with the number of Claude calls (writer + checker), tokens and cost (ADR 0002 guardrail 4; `--n` is the limit). Exit code 0 = the writer bar is met.

**`taken_ids` and `taken_questions` from the CLI:** the ids and questions in every `data/cards/*.jsonl` **except** the topic's own file (with `--replace` its old ids are free again); with **`--add`** the topic's own file counts too (its ids stay taken, its questions aren't asked again). No cards yet (no folder, no files, or only blank files) = empty. If any other card file has a bad line or a repeated id, it prints one line ("the card bank has a problem …") and exits 1 without calling Claude, so new ids never clash with cards it couldn't read. Without `--add` the topic's own file is not read, so a broken one can still be replaced; with `--add`, or a `--dry-run` without `--replace`, a broken topic file is a bank problem (exit 1). The CLI looks `write_cards` up on the `cli` module, so a test can replace `longevity_trainer.cli.write_cards`.

## Outputs
| Output | Type | Plain meaning |
|---|---|---|
| `write_cards` | `WriterResult` | `kept: list[LongevityCard]` (in draft order), `drops: list[Drop]`, `report: WriterReport` |
| `Draft` | pydantic model | One drafted card as Claude returns it: `asks` (`"what"`, `"how"`, `"how_sure"`, `"catch"` or `"connect"`: which question it answers), `kind` (`name`/`fact`/`term`/`explain`), `question`, `answers` (1+), `quote` (copied word for word from the source), `links_to` (`str`: the id of the other topic a connect card links to; `""` for every other ask; the reply schema requires it, but a draft without the key is read as `""`) |
| `Drop` | pydantic model | `question` (the draft's), `gate` (`"shape"`, `"link"`, `"quote"`, `"repeat"` or `"checker"`), `reason` (one line) |
| `WriterReport` | pydantic model | `drafted`, `kept`, `dropped_shape`, `dropped_link`, `dropped_quote`, `dropped_repeat`, `dropped_checker`, `checker_errors`, `asks_kept` (the distinct `asks` values among kept cards, sorted, each once), `model`, `prompt_version`, and `passed` (kept in `model_dump()`) |
| `PROMPT_VERSION` | `str` | Bumped when the prompt changes; in every report |
| `slug` | `str` | `slug("Epigenetic clocks!")` → `"epigenetic-clocks"` |
| `ASKS` | `tuple[str, ...]` | The five asks in order: `("what", "how", "how_sure", "catch", "connect")` (the CLI's coverage line) |
| `REQUIRED_ASKS` | `set[str]` | `{"what", "how", "how_sure"}`: the asks every topic should cover (coverage line). `connect` is welcome but not required: some topics have no link their source states |
| `TOPICS_FILE` | `Path` | `ROOT / "data" / "topics.jsonl"` |
| `load_topics` | `(path=None) -> dict[str, str]` (None = `TOPICS_FILE`, looked up when called) | The topics with `"status": "v1"`, id → `topic` text, in file order; blank lines skipped. Raises `FileNotFoundError` if the file is missing and `ValueError` (naming the line number) on a line that isn't a JSON object with string `id`, `topic` and `status`, or on a repeated id |

**Card ids:** `<topic-slug>-<asks>-<k>` with `_` in `asks` turned into `-` (e.g. `rapamycin-how-sure-1`). Only **kept** cards are numbered: `k` counts from 1 per `asks` value over the kept cards, in draft order, skipping any id in `taken_ids`. (The checker sees each card with a provisional id; the id plays no part in its verdict.)

**Receipts:** `source` = `source_id`; `quote` = the draft's quote; `page` = the page `receipts.find_quote` finds it on (1 for html and jats-xml). With `pages`, the quote gate searches only the chosen pages (a quote not on them is dropped), but `page` is the **first** page of the **whole** source the quote is on, which is what `check-receipts` expects: usually the chosen page's real number (a quote found on the 2nd chosen page of `(9, 12)` gets page 10), but a sentence that also appears earlier (e.g. in the abstract on page 1) gets page 1.

**The gates, in order** (a draft that fails one is dropped there, with a `Drop`):
1. **shape:** the draft makes a valid `LongevityCard` (e.g. question ≥ 10 characters, no blank answer, quote key ≥ 20 characters)
2. **quote:** `find_quote` finds the quote in the source's page keys
3. **link:** a `connect` draft's `links_to`, slugged (`" mTOR "` → `mtor`; topic ids are slugs), must be a key of `topics` and not the topic itself (`links_to == slug(topic)`); reasons: `"connect card has no links_to"`, `"links_to '<x>' is not a known topic"`, `"links_to '<x>' is this card's own topic"`. Any other draft must have `links_to` blank (nothing left after slugging): reason `"only connect cards link to a topic"`. The link isn't stored on the card (the card format is unchanged); the question and answer carry it, and the quote must state it. **Known limit:** "own topic" is only caught when the topic's slug is its topic id; a topic written under another name (e.g. `physical-activity`, whose id is `exercise`) isn't left out of the list, and a link to its own id passes this gate (the checker may still catch it). Mapping card topics to topic ids is in FUTURE. **Also:** the gate checks the link is a real topic, not that the card is about it (a card about mTOR with `links_to` `ampk` passes it); the checker judges the card itself, and that's in FUTURE too
4. **repeat:** a question already kept in this run, or in `taken_questions`, compared case- and space-insensitively, is dropped (reason says which: "same question as an earlier card" or "already in the bank"; a question the checker rejected, or errored on, doesn't block a later draft with the same wording)
5. **checker:** `check(card)`; `ok=False` drops it with the checker's rules and reason; a `ClaudeError` from the checker drops it too (gate `"checker"`, reason starting `"checker error"`) and counts in `checker_errors`

**The writer bar** (`passed`): `drafted > 0`; at least 80% of drafts pass the quote gate (`dropped_quote <= drafted * 0.2`: a writer that invents quotes is broken, so nothing from that run is trusted); and `kept >= 1`. Every kept card has passed every gate, so it is saved even if the run didn't cover every ask or kept few cards (user, 2026-11-12: runs kept 3-4 good cards and threw them away for missing one ask). **Coverage** (what / how / how_sure: rule 1, never names alone; rule 2, every intervention gets a "how sure" card) is a goal for the **topic**, reached over runs with `--add`, and shown by the CLI's coverage line; `asks_kept` still reports what this run added.

What the prompt contains:
- **System:** you write quiz cards for someone learning longevity science; the whole of `docs/LEARNING_GOALS.md`, word for word, read at import (its own §4 says the writer's prompt includes it); write `n` cards on the topic from the source text below and nothing else; every card's quote must be copied **exactly** from the source (a script checks it), one to three consecutive sentences, never paraphrased; **the quote alone must back the whole card** (one short claim per answer, taken from the quote; the question asserts nothing the quote doesn't; no open lists); if the source is split into `[page N]` parts, each quote must come from inside one page; cover what / how / how sure / catch; name the population in any "how sure" answer; no trivia (sample sizes, p-values, registry numbers); questions must stand alone (no "the trial", "the authors", "Figure 2"); no trend questions; **connect** cards: a question that links this topic to ONE other topic from the list (what it acts on, which hallmark or pathway it belongs to, what it's measured by, which trial tested it), asked in the source's own words without saying "topic" (e.g. "Which kinase complex does rapamycin inhibit?" → "mTORC1 (mTOR)"), answered with the name as the quote gives it (not the list's description), `links_to` set to that topic's id, and a quote that states the link; for every other card `links_to` is `""`; write at least one connect card whenever the source states a link to a listed topic (the dry run of v5 without this line wrote none).
- **Prompt:** the topic, `n`, the source's title, the list of topics a connect card may link to (one line each, `- <id>: <topic text>`, under a line naming them as the topics to connect to, own topic left out; if none are left, one line saying to write no connect cards instead), and its full plain text (`source_text.text_pages`). A one-page source (html, jats-xml, a one-page PDF) is its text as is; a source with 2+ pages has each page start with a line `[page N]` (N from 1), pages joined with blank lines, because `find_quote` looks for a quote on one page at a time and a quote across a page break would always be dropped.
- When `taken_questions` isn't empty, the prompt also lists them under a line saying these questions are already in the bank and must not be asked again, even in other words (so `--add` runs bring new facts, not rewordings).
- `PROMPT_VERSION` is `"5"` (v2 added "the quote alone must back the whole card"; v3 the page markers; v4 the questions already in the bank; v5 connect cards and the topic list).
- **Reply schema:** `{"cards": [Draft, ...]}`.

## Failure modes
| Situation | What it does |
|---|---|
| `docs/LEARNING_GOALS.md` is missing | Raises `RuntimeError` at import: a writer without its standard must not run |
| The record `<source_id>.json` holds a different `id` | Raises `ValueError` ("<source_id>.json is for '<id>'") before any Claude call |
| No record `data/sources/<source_id>.json`, or the document can't be fetched or verified | Raises (`FileNotFoundError` / `DownloadError`), before any Claude call; the CLI prints one line, exit 1 |
| The text going to Claude (the chosen pages, or the whole source) is over 200,000 characters | Raises `ValueError` ("source too long …") before any Claude call (too big for one call; split it later) |
| `n` outside 1–20 | Raises `ValueError` |
| `pages` with first < 1, last < first, or last beyond the source's page count | Raises `ValueError` naming the source's page count, before any Claude call |
| An empty or unsluggable topic (`"!!!"`) | Raises `ValueError` |
| Claude can't be reached, or its reply isn't valid JSON or breaks the schema | Raises `ClaudeError` ("bad reply: …"); nothing is written |
| Claude returns more cards than asked | Only the first `n` are used |
| `data/topics.jsonl` is missing or has a bad line (and `topics` wasn't given) | `load_topics` raises (`FileNotFoundError` / `ValueError`) before the source is read or fetched and before any Claude call; the CLI prints one line, exit 1 |
| Claude returns 0 cards | A report with `drafted=0`, `passed=False` |
| The checker fails on one card | That card is dropped (`checker error`), the run goes on |
| `data/cards/<slug>.jsonl` exists (CLI, no `--replace`, no `--dry-run`) | Exit 1 with one line; nothing drafted (checked before calling Claude). With `--dry-run` it goes ahead (nothing is written) |
| Another card file has a bad line or repeated id (CLI) | Exit 1 with one line; nothing drafted |
| The card file can't be written (CLI) | Exit 1 with one line; the old file is unchanged |
| Every draft dropped, or the report doesn't pass | Nothing written; exit 1 |
| A draft with an `asks` or `kind` value outside the lists | The reply breaks the schema: `ClaudeError` ("bad reply"); a too-short question or blank answer is the `shape` gate instead |

## How to test
Automatic tests in `tests/blocks/test_card_writer.py`, with a **fake `ask`** and a **fake `check`** (never real Claude), and small source files written in the test (an html source with a matching `Source` record and fake fetch, or a pre-placed file whose size and SHA-256 match):
- **Prompt:** the system prompt contains the whole of `docs/LEARNING_GOALS.md`; the user prompt contains the topic and the source text; the schema and model are passed; `n` is in the prompt
- **Gates:** a draft with a 5-character question → `shape`; a quote not in the source → `quote`; the same question twice (different case/spacing) → second is `repeat`; the same question twice where the checker rejects the first → the second is checked (and kept if it passes), not `repeat`; checker `ok=False` → `checker` with its reason; checker raising `ClaudeError` → `checker`, `checker_errors` 1, run goes on; drops are listed in draft order
- **Cards:** ids follow `<slug>-<asks>-<k>` (`how_sure` → `how-sure`), skip `taken_ids` and repeats within the run; receipt source/quote/page are right (page from `find_quote`, e.g. 2 for a two-page PDF-like source of page keys); topic is the given topic
- **Report and bar:** counts add up (`kept + all drops == drafted`, `dropped_link` included); passes with ≥80% quotes found and ≥1 kept, **also** when only one ask was kept and when fewer than half were kept (e.g. 1 of 8); fails when 3 of 10 quotes are missing (even with cards kept), when nothing was kept, and when nothing was drafted; `model_dump()` has `passed`
- **`taken_questions`:** a draft whose question matches one in `taken_questions` (different case/spacing) is dropped at `repeat` with "already in the bank", before the checker is called; the prompt lists every taken question; with none, the prompt has no such list; `PROMPT_VERSION == "5"`
- **Receipt page with `pages`:** a quote on page 1 and again on page 3 of a 3-page source, with `pages=(3, 3)`, is kept with receipt page 1; a quote only on page 1 with `pages=(3, 3)` is dropped at `quote`
- **Connect cards (`topics` given):** a connect draft with `links_to="mtor"` (a key of `topics`) is kept with id `<slug>-connect-1` and `"connect"` in `asks_kept`; `" mtor "` and `"mTOR"` are kept too; with `topics={}` (or only the own topic) the prompt says to write no connect cards and has no topic list; a missing topics file raises before `fetch` is called; blank `links_to` → `link` ("has no links_to"); `"made-up"` → `link` ("not a known topic"); the topic's own slug → `link` ("own topic"); a `what` draft with `links_to="mtor"` → `link` ("only connect cards"); the quote gate comes first (a connect draft with a bad link and a missing quote is dropped at `quote`, so invented quotes always count against the bar); a `link` drop comes before the checker, which isn't called for it; the system prompt mentions connect cards, `links_to` and "at least one connect card"; the prompt lists each topic as `- <id>: <text>` but not the card's own topic; `ASKS` ends with `"connect"` and `REQUIRED_ASKS` doesn't include it; with `topics=None`, `load_topics()` is used (monkeypatch `TOPICS_FILE`); other tests pass a small `topics` dict, so they don't depend on the real `data/topics.jsonl`
- **`load_topics`:** keeps only `v1` lines, id → topic text, in file order; skips blank lines; a missing file → `FileNotFoundError`; a line that isn't JSON, isn't an object, or lacks a string `id`/`topic`/`status` → `ValueError` naming the line number; a repeated id → `ValueError`; the real `data/topics.jsonl` loads and includes `mtor` and `rapamycin` and not `glp1-price` (after-m5)
- **CLI coverage with connect:** a topic file with a `-connect-` id lists connect among the covered asks; a file without one doesn't report connect missing; the report line includes `link <n>`
- **Bar, kept 0:** quotes all fine but every draft dropped at `shape` → not passed
- **`pages`:** with a 3-page source and `pages=(2, 3)`, the prompt has page 2's and page 3's text, not page 1's, marked `[page 2]` and `[page 3]` (the real numbers); a quote only on page 1 is dropped at `quote`; a quote on page 3 gets receipt page 3; `pages=(2, 2)` sends one page with no marker; `(0, 1)`, `(2, 1)` and `(1, 4)` raise `ValueError` without calling Claude; a whole source over the limit passes when the chosen pages are under it
- **CLI `--pages`:** `--pages 17-20` passes `pages=(17, 20)` to `write_cards`, `--pages 5` passes `(5, 5)`, no flag passes `None`; `--pages x`, `5-`, `0-3` and `9-4` exit 2 and `write_cards` isn't called
- **Prompt pages:** a one-page source has no `[page` marker in the prompt; a two-page source has `[page 1]` before page 1's text and `[page 2]` before page 2's
- **Errors:** missing source record, a record whose `id` isn't `source_id` → `ValueError` before any Claude call, too-long source, `n` 0 and 21, topic `"!!!"`, a bad reply → `ClaudeError`, more than `n` drafts → first `n` used
- **slug:** `"Epigenetic clocks!"` → `"epigenetic-clocks"`, `"  mTOR  "` → `"mtor"`
- **CLI** (fake `write_cards`): writes `data/cards/<slug>.jsonl` under a temporary `CARDS_DIR` (monkeypatch `longevity_trainer.cli.CARDS_DIR`); `--dry-run` writes nothing; an existing file without `--add` or `--replace` → exit 1 and `write_cards` not called; `--add` keeps the old lines first and appends the new cards; `--add` passes `taken_ids` and `taken_questions` that include the topic file's own ids and questions (and the other files'); without `--add`, `taken_questions` holds the other files' questions only; `--add` with no file yet writes it; `--add --replace` exits 2; the coverage line names the asks covered and says what's missing (e.g. a file with only `-what-` and `-how-sure-` ids → missing how); a `--dry-run` (no `--add`) on a topic whose file has a `-how-` card doesn't report how missing, and passes that file's ids and questions as taken; a run that doesn't pass still prints the coverage line; a failed write prints none; if the topic file changes during the run (the fake `write_cards` edits it), nothing is written and it exits 1; with `--replace` it's overwritten; exit 1 when the report doesn't pass or nothing was kept; the written lines load back with `load_cards`; `--dry-run` with the file already there calls `write_cards` and writes nothing; `write_cards` gets `taken_ids` = the ids in the other card files, not those in the topic's own file; another card file with a bad line → exit 1 and `write_cards` not called; a broken topic file is still replaced with `--replace`; no `.tmp` file is left behind; the output includes a line with "Claude calls"
- **Contract test:** folder parts exist and `BLOCK_SPEC` matches this SPEC

**The writer eval (by hand, real Claude):** `write-cards --dry-run` on 3 topics (rapamycin / `pearl-2025`, epigenetic clocks / `measuring-biological-aging-2020`, physical activity / `who-physical-activity`). Its bar is stricter than the save bar, because it measures the prompt's quality, not whether a run's cards may be saved: across the 3 runs, 0 invented quotes, at least half of all drafts kept, and each topic covering what / how / how_sure within 2 runs (with `--add`). Then the user spot-checks 10 kept cards 👍/👎; every 👎 becomes a rule in LEARNING_GOALS or a line in the exam.
